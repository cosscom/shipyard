# Stopping agents from the Agent Dashboard

Stopping ends an agent's session on its box (`app/src/views/dashboard/stop.tsx`). Its worktree and files stay unless the bulk dialog is told to archive them. The bulk dialog only asks: once confirmed it closes, and the run goes on as a job in the background-jobs tray (`components/jobs-tray.tsx`, store `lib/jobs.ts`, runner `lib/stop-job.ts`). A box with runs does its share itself, as one `stop` run (`internal/box/runs/templates/stop.json`, leaves `stop_session` and `archive_worktree` in `internal/box/runstop.go`, client `lib/stop-on-box.ts`): the job only follows it, so it goes on while the laptop sleeps or the app is closed, and a row fails only when the box says so. The job is kept (`berth.jobs.stopRuns`) before the start is sent, and a box that doesn't answer the start is asked again under the same idempotency key until it does (`startStopRun`), its rows `Waiting for BOX`; **Stop the rest** meanwhile asks the box for the run by its group: one it took is cancelled, and with none the rows read `Not stopped`. Only a box that answers neither reads `Failed: BOX didn't answer, so it may still stop it`. The box applies the same safety rules (never forced, branch kept, dirty / another agent / a failed stop keep it, the `session.stop` and `worktree.remove` before:-gates) and waits for the archive script, so a row reads `Archived` where the app's own loop said `Archiving`. A worktree already on its way out is joined, never archived twice (`dropBegin` in `dropWorktree`), and reads `Archived` once that archive is done. The box's stop runs archive one worktree at a time between them (`archiveTurn`), each looking for agents when its turn comes, and no session starts between that last look and the folder going (`removeAfter`). Boxes without runs, offline at the start, or from before stop runs (the start is refused) get the app's own loop below, for their rows only. The app's loop archives through `removeWorktreeOnBox(…, "archive")` (`lib/remove-worktree.ts`), the same path as the sidebar's Archive… and the Worktrees table's bulk archive, in the same per-box line (`inTurn`). `lib/archive-after-stop.ts` decides which worktrees to archive and which to keep. Unit tests sit next to each of these. The box refuses a worktree with uncommitted or untracked files before it stops its sessions and services or runs the archive script (`dropWorktree` in `internal/box/api.go`), in git's words, so every Archive path keeps dirty work up front. A bulk Stop still stops the agents it was asked to stop: what's kept for uncommitted changes is the worktree and its files, not the agents running.

## Sub-features

- `stop-one`: a card's ⋯ → **Stop agent…** (asks first) and **Stop and remove worktree** (removes it without asking; git keeps a dirty one, and a toast offers Remove anyway).
- `stop-picked`: **Select**, click cards, **Stop N…** (or ⌫). Also a column's ⋯ → **Stop all N in <column>…**. The dialog lists them by box, each with a checkbox. A busy one says "working" or "needs you".
- `cleanup`: **Clean up…** in the header, or a Done/Ready column's ⋯ → **Clean up idle agents…**. It ticks the ones idle longer than 1 hour / 4 hours / 1 day (remembered in `berth.dashboard.cleanupAfter`). A parked agent is listed but never ticked for you.
- `stop-archive`: in both bulk dialogs, **Archive their worktrees where it's safe**. It shows only when a ticked row has a worktree that isn't the main checkout, starts unticked, and is remembered (`berth.dashboard.stopArchives`). Ticked, the agents stop first. Then each of their worktrees is archived once: one at a time on each box, the boxes side by side. A row reads `Stopped · Archived; its branch is kept`, `Stopped · Archiving: its archive script runs, then it goes` (the location has an archive script), `Stopped · Kept: uncommitted changes` (git refused), `Stopped · Kept: another agent is still running there` (an agent session outside the batch is live in it or in a folder under it, by the box's own fresh listing; plain shells and services don't count), `Stopped · Kept: an agent there didn't stop`, `Stopped · Kept: couldn't check for other agents on its box` (its box didn't answer the listing), or `Stopped · Couldn't archive: …` in the box's words: git's own, or when git said nothing how it ended (`git worktree remove timed out after 10 min and was stopped; …`, `… was stopped (signal: killed) and said nothing`, `… failed with no output (exit status 1)`), never a bare `git worktree remove:`.
- `stop-tray`: confirming closes the dialog at once (under 1 s). The tray sits bottom right, above the status bar, the loops panel and a page's floating bar (the board's selection bar), with toasts above it. Its job reads `Stopping N agents · k/N` with every row grouped by box (`devl 3/3`), each `Waiting to stop`, `Stopping…`, `Stopped`, `Stopped · waiting to archive`, `Archiving…`, then its outcome; a stop that fails reads `Failed: …`. The chevron (**Fold**) folds the tray to one line with a spinner, remembered in `berth.jobs.folded`. **Stop the rest** sends nothing more, archives waiting their turn included: what was sent finishes, and the rest read `Not stopped` (or `Stopped · Not archived`). A worktree waiting to archive is marked Archiving… in the sidebar at once, so Archive… there leaves it be. In the app's own loop, one already on its way out reads `Stopped · Already being archived` and isn't asked for again; a box's run waits for that archive instead and reads `Archived`. The app's loop holds a box's line until the box says an archive script finished (`archiveEnded`), so a row reads `Archiving: …` and then `Archived; its branch is kept`. When its turn comes, the box's listing is read again, so an agent started there meanwhile keeps it (`Kept: another agent is still running there`). A clean run shows the old toast ("Stopped N agents · archived M worktrees") and a one-line summary ("17 stopped, 15 archived") that fades after about 10 s. Anything kept, failed or not sent leaves a report, the summary ("4 stopped, 1 archived, 1 archiving, 2 kept") over just those rows, until **Dismiss** (×). The job carries on if you leave the board. On a box with runs, **Stop the rest** cancels the box's run: the step in flight finishes there, the rest read `Not stopped` / `Stopped · Not archived`.
- `stop-reattach`: a job whose rows a box runs is kept in `berth.jobs.stopRuns` (its runs, their params and rows) from before its start is sent until it's dismissed, or for 24 hours at most: a run's journal goes after a while, so a job older than that isn't brought back. After a relaunch the tray brings it back, rows `Waiting for its box` until the box answers, then as the box's run is now or as it ended. A share whose start was never answered is asked for again under the same key: the box has it, or takes it then. A job you pressed **Stop the rest** on is kept as cancelled (`onCancel`) and comes back cancelled: an unanswered share is only looked up by its group, its run cancelled if the box took it, and never sent again. A laptop that sleeps mid-run just reads the run again when it wakes. The app's own loop (boxes without runs) still doesn't survive the app quitting.

## How to get to it (user POV)

- ⌘J opens the Agent Dashboard. **Select**, click cards, then **Stop N…** in the bar at the bottom.

## Driving it with drive.mjs

- `node .claude/skills/verify-berthd/scripts/drive.mjs dashboard-stop-archive --port $PORT` opens the mock with `noruns` (the app's own loop, for boxes without runs), `slowremove=4000` and `slowstop=1500`, and picks four agents. It covers each outcome: search-perf archives through shop's archive script, ci-flake on gpu archives after gpu's 4 s, checkout-fix is kept for uncommitted changes, and order-export is kept because two more agents run there. It ticks the box and stops them, and fails if the dialog stays open over 1 s. Then it shoots the tray mid-run (ci-flake `Archiving…`), folds it, opens the Worktrees view while the job runs, and checks the report rows and the table (two gone, two still there). It also checks that **Clean up…** opens with the box ticked, that a clean one-agent run fades on its own, and that **Stop the rest** leaves one of four `Not stopped`.
- On a real box, the tray end to end: `scripts/dev-box.sh up`, `eval "$(scripts/dev-box.sh env)"`, then `drive.mjs dashboard-stop-live --port $PORT --agent http://127.0.0.1:9378`. It makes its own worktrees of acme-shop (`verify-stop-a/b/c`, a Claude Code in each; `verify-stop-c` gets an uncommitted file; and `verify-solo`). It stops the three with archiving ticked, expects the report `3 stopped, 2 archived, 1 kept`, and reads `git worktree list` and `git branch` on the box: a and b gone, c still there, every branch kept. No request is refused: the box keeps verify-stop-c inside its run, and the scenario reads the box's stop runs back (`Stopping 3 agents: succeeded`). Then it archives `verify-solo` from the sidebar, waits for **Archived verify-solo** in the tray, checks git again, and finds that one a stop run on the box too (`Archive verify-solo: succeeded`). `dev-box.sh down` removes it all. It never touches a session it didn't start.
- On a real box: `scripts/dev-box.sh up`, then `scripts/archive-dirty-live.sh` archives a dirty and a clean worktree of acme-shop under an archive script, through the agent's API. The dirty one is refused at once (400, "contains modified or untracked files"), and its file stays while the script doesn't run. The clean one answers 202, the script runs in it, and it goes. `dev-box.sh down` afterwards.
- The lid closing, on a real box: `scripts/dev-box.sh up`, `eval "$(scripts/dev-box.sh env)"`, then `drive.mjs dashboard-stop-lid --port $PORT --agent http://127.0.0.1:9378`. It makes seven throwaway worktrees of acme-shop with a Claude Code in each (`verify-lid-dirty` gets an uncommitted file, `verify-lid-shared` a second agent outside the batch), gives acme-shop a 6 s archive script, stops five with archiving ticked, and pauses the laptop agent (SIGSTOP) for 25 s while the box archives. Woken, the tray must read `5 stopped, 3 archived, 2 kept`, and git on the box agrees (branches kept, the outsider still running). Then it stops the other two and reloads the page mid-run: the job comes back from the box and ends `2 stopped, 2 archived`.
- The box going away as Stop is pressed, on a real box: `scripts/dev-box.sh up`, `eval "$(scripts/dev-box.sh env)"`, then `drive.mjs dashboard-stop-unanswered --port $PORT --agent http://127.0.0.1:9378` (with `VERIFY_BOX_DIR` if `up` had one). It makes two throwaway worktrees with a Claude Code in each, presses Stop with archiving ticked and kills the box's berthd (SIGKILL) at once, and starts it again 20 s later as `dev-box.sh up` does (its pid goes back in `berthd.pid`). Meanwhile no row may fail; they read `Waiting for devq` when the start went unanswered. Back, the job must end `2 stopped, 2 archived`, the box must have exactly one stop run for it (whether it took the first ask and resumed it, or took the ask sent again under the same key), and git agrees.
- A removal git doesn't finish, on a real box: `scripts/dev-box.sh up`, `eval "$(scripts/dev-box.sh env)"`, then `drive.mjs dashboard-stop-interrupted-live --port $PORT --agent http://127.0.0.1:9378` (with `VERIFY_BOX_DIR` if `up` had one). It restarts the box with a git on its PATH that, for `verify-slow` only, deletes the worktree's `.git` and `.gitignore` and then hangs, as a big folder's `git worktree remove` on a busy box did: acme-shop gets a committed `.gitignore` for `node_modules` first, and `verify-slow` a `node_modules`, so what's left holds files that only the lost `.gitignore` ignored, and with `BERTH_WORKTREE_REMOVE_TIMEOUT=5s`. It stops `verify-slow` and `verify-ok` with archiving ticked. The report must read `2 stopped, 1 archived, 1 failed`, and the failed row `Stopped · Couldn't archive: git worktree remove timed out after 5s and was stopped; the folder may be partly removed, and archiving it again finishes it`, never a bare `git worktree remove:`. git lists `verify-slow` as prunable with its files still there. Then **Archive…** from the sidebar finishes it: **Archived verify-slow**, the folder gone, git no longer lists it, both branches kept. At the end the box is restarted with its own git. `VERIFY_BERTHD=<old berthd>` runs it on another build for a before: the old box stops git after 60 s and the row ends at `git worktree remove:`. Make a fresh dev box for each pass (`down`, `up`), as it makes fixed-name worktrees.
- `app/e2e/dashboard-stop-archive.spec.ts` asserts the same on the mock, where devl and gpu play their stop runs out (`playStop` in `lib/mock-runs.ts`), plus `?noruns` (every box from before runs: the app's own loop, an archive script still running reads `archiving`), unticked (nothing archived, the old copy and toast), a main checkout alone (no box) and leaving the board mid-run.

## Gotchas

- With the default prefs the sidebar is the rail layout, which shows one project at a time. Read the outcome in the Worktrees table, or open with `labs: false` prefs, as the e2e does, to use the sidebar's `worktree-row`s.
- In the mock, checkout-fix's agent is in Needs you, not Done: it is the only dirty worktree in the fixtures.
- The mock's archive script takes 1.5s, so search-perf leaves the table a moment after its row says Archiving.
- `?slowremove` slows only a worktree with no archive script (ci-flake); `?slowstop=MS` slows every stop's answer, which is what lets a test press **Stop the rest** with rows still unsent. `?noruns` takes `runs` out of every box's capabilities, for the app's own loop.
- The mock's stop run waits 1.6 s for shop's archive script, as a box does, so search-perf reads `Archived`, not `Archiving`, on devl.
- The tray is `getByRole("region", { name: "Background jobs" })`, a job `getByRole("group", { name: "Stopping N agents" })` (its first title, kept after it ends), its rows `listitem`s.
- axe over the open dialog flags the board's cards behind it (`.opacity-70` meta text), not the dialog.
