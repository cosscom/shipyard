# Archiving and removing a worktree

A worktree that is done goes one of two ways. **Archive…** asks first, then stops its sessions and services, runs the repo's archive script if it has one, and removes the folder; the branch stays, except a review worktree's own `review/` branch, which goes with it. **Remove worktree** asks nothing and removes it; the branch stays too, with the same exception. Both go through one queue (`app/src/lib/remove-worktree.ts`): the worktree is marked at once (`lib/removing.ts`), and each box takes one removal at a time, so archiving several in a row never waits on a dialog. On a box with runs, Archive… is a one-worktree `stop` run there (`archiveOnBox`, as the board's bulk Stop: `features/dashboard-stop.md`): its sessions stop, then it's archived where it's safe, in the box's own line (`archiveTurn`), and it finishes while the laptop sleeps or the app is closed. Elsewhere, and for Remove, the app sends it in the box's line (`inTurn`), which it holds until the box says the worktree went or the script failed (`archiveEnded`).

## Sub-features

- `archive-confirm`: the dialog names the worktree, its branch ("Branch … stays") and the archive script, if any. It closes as soon as Archive is pressed, before the box answers.
- `archive-mark`: from that moment the row is struck through and says **Archiving…** (`[data-leaving]`, `LeavingRow` in `components/sidebar/projects.tsx`); zen's switcher says the same, and the worktree's launcher says "Archiving NAME…". It can't be opened meanwhile.
- `archive-tray`: the archive is also a one-row job in the background-jobs tray (`queueRemoval(…, { kind: "archive" })`, `components/jobs-tray.tsx`): **Archiving NAME**, its row `Waiting for BOX` until its turn (or until the box answers), then `Archiving…` (and `Archiving: its archive script runs, then it goes` while the app waits on a script). Once the worktree is gone it reads **Archived NAME** and fades; kept, it stays as a report **Kept NAME** / `Kept: uncommitted changes` (or the box's other reason, such as `Kept: another agent is still running there`) until dismissed. Only Archive… from the sidebar, zen and the launcher uses the tray; Remove and the Worktrees table don't.
- `archive-done`: without a script the box answers once the folder is gone, then a toast **Archived NAME** / "Branch … is kept." With a script the box answers at once: a toast **Archiving NAME** / "Its archive script is running on the box…", and **Archived NAME** when `worktree.removed` arrives. On a box with runs it is one toast, **Archived NAME**, once the box's run has the worktree gone; kept there, **Couldn't archive NAME** says why.
- `archive-dirty`: uncommitted work makes git refuse. The worktree comes back as it was, with a warning toast **Couldn't archive NAME** / "NAME has uncommitted changes, so it was left as it is. Commit them first, or use Remove worktree to discard them."
- `archive-queue`: archives (and removals) on one box go one after another; each row keeps its mark until its turn is done, archive script included. Another box's don't wait.
- `remove`: Remove worktree, the dashboard's Stop and remove worktree, and Delete in the Worktrees table: no dialog, **Removing…**, and a dirty one gives **Kept NAME** with **Remove anyway**.
- `archive-interrupted`: git has 10 minutes to remove a worktree (`BERTH_WORKTREE_REMOVE_TIMEOUT` on the box sets another limit). One it doesn't finish in time is stopped, and the row says so (`git worktree remove timed out after … and was stopped; the folder may be partly removed, and archiving it again finishes it`). A removal stopped halfway leaves a folder with no `.git`, which git lists as prunable and the sidebar still shows. Archive… on it removes what's left and git's record of that one worktree (never `git worktree prune`, which would drop every half-removed one's), keeps the branch, and reads **Archived NAME**. It does so only when git, asked through the record's HEAD and index, sees nothing but files already deleted (any `.gitignore` the removal deleted is put back as committed first, so `node_modules` doesn't read as new); a changed or new file keeps it as `Kept: uncommitted changes`. So does one whose folder is gone altogether, which isn't listed. A folder that still has a `.git` is never deleted by hand.
- Bulk Archive in the Worktrees table (`views/worktrees/archive-dialog.tsx`) is separate: its dialog stays open on purpose, with each row's outcome (`use-bulk.ts`). On a box with runs, its eligible rows (and Stop sessions') are one `stop` run there (`startOnBoxes`, as the board's bulk Stop): the worktree's sessions stop first, then it's archived where it's safe, and a row the box keeps reads `Kept: …` (skipped). A row with uncommitted changes and every row of a box without runs go one after another from the app, as before; a row already on its way out is skipped (`already on its way out`) and left to that removal.

## How to get to it (user POV)

- Right-click a worktree in the sidebar, or its ⋯: **Archive…** or **Remove worktree**. Zen's worktree menu has the same items.
- A worktree with no tabs shows its launcher: **Archive this worktree…**.
- Worktrees (sidebar): select rows, then **Archive N…** or **Delete** in the bar at the bottom.

## Driving it with drive.mjs

- `node .claude/skills/verify-berthd/scripts/drive.mjs worktree-archive --port $PORT` opens the mock with `slowremove=4000` (a box takes 4 s to remove a worktree with no archive script, as a big `node_modules` does) and the list sidebar. It archives `gpu/ci-flake` and fails if the dialog stays open over 1 s, checks its row and its tray job say Archiving…, archives `gpu/judge-v2` straight after (both marked; judge-v2 waits its turn, `Waiting for gpu` in the tray), waits for **Archived ci-flake** with "Branch me/ci-flake is kept." at about 4 s and **Archived judge-v2** at about 8 s, then archives `devl/qa-deck` (script `pnpm db:drop`: **Archiving qa-deck**, then **Archived qa-deck**) and `devl/checkout-fix` (uncommitted: **Couldn't archive checkout-fix**, row still there, and a **Kept checkout-fix** report in the tray, then dismissed). Each step logs how long the dialog stayed open.
- Hooks: `[data-testid=worktree-row][data-worktree="BOX/NAME"]` for a row, `[data-leaving]` with the name's text for its leaving state, `getByRole("alertdialog")` for the dialog and its exact **Archive** button, `[data-slot=toast-viewport] > *` with the title's text for a toast.
- `app/e2e/worktree-remove.spec.ts` asserts the same on the mock: Remove (no dialog, Remove anyway), Archive (dialog gone in 1 s with `slowremove`, Archiving…, the toast) and Delete in the table.

## Gotchas

- `?slowremove=MS` slows only a worktree with no archive script; one with a script (devl's shop) answers at once and finishes 1.5 s later, as on a box. `checkout-fix` always refuses without force.
- The default sidebar is the rail, which shows one project at a time; the scenario sets `sidebar=list` to see devl's and gpu's worktrees together, as the e2e specs do.
- A worktree already marked is ignored by a second Archive or Remove until its mark goes.
- `dashboard-stop-interrupted-live` (see [dashboard-stop.md](dashboard-stop.md)) drives `archive-interrupted` on a real box, with a git that hangs for one worktree.
- The real box's slow part (deleting a big folder inside `git worktree remove`) isn't in the mock; a real box is needed to time it (`../scripts/dev-box.sh`). `dashboard-stop-live` (see [dashboard-stop.md](dashboard-stop.md)) archives `verify-solo` from the sidebar on one and checks git agrees.
