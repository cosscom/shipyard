---
title: berthd CLI
description: Every command of berthd, the daemon on each box, and what agents on the box use.
---

`berthd` runs on each box. `berthd serve` is the daemon; most other commands
talk to it through its local socket, so tools and agents on the box (hooks,
flows, skills) can drive it directly. `berthd help` prints this list.

- **Addressing.** A location is `shop`, a worktree `shop/checkout`, a session by
  its name. From the laptop, [`berth`](/reference/cli) takes the same
  commands with the box in front: `berth sessions devl`,
  `berth exec devl/shop/checkout -- …`.
- **JSON.** Every listing takes `--json`.
- **State.** `BERTH_HOME` overrides the state directory. Hooks run from
  `~/.berth/hooks.json` and `~/.berth/plugins`.

## The daemon

| Command | What it does |
| --- | --- |
| `berthd serve [--listen ADDR]` | Serve paired laptops (default: the tailnet address only, port 7444) |
| `berthd install [--listen ADDR] [--keep-listen] [--no-integrations] [--no-tools] [--dry-run]` | Run `serve` as a user service (systemd, or launchd on macOS), and install hooks and skills for the agent CLIs found on the box (`--no-integrations` skips that). First it installs tmux, and git if missing, when that needs no password (as root, with sudo that needs none, or with Homebrew), and otherwise stops with the command to run (`--no-tools` skips this). `--keep-listen` keeps an installed service's non-tailnet address; `--dry-run` checks the box and prints what it would do |
| `berthd uninstall` | Remove that service |
| `berthd agents install [--integrations] [--markers] claude\|codex\|cursor\|opencode ...` | Install agent CLIs for this user into `~/.local/bin`, without sudo, each skipped when it is already there: Claude Code with its native installer, Codex from its pinned GitHub release (sha256 checked), Cursor Agent and OpenCode with their own installers. Adds `~/.local/bin` to the login shell's `PATH` if it lacks it. `--integrations` then installs hooks and skills for every agent CLI here; `--markers` prints a `::berth-step` line as each starts and ends. The guided install over SSH, a team setup's `agents` and **Add agents…** in the app run it |
| `berthd agents list [--json]` | Which agent CLIs are here, and how to add the others. An agent counts wherever your interactive shell finds it, an npm install under nvm too ([agent CLIs you installed yourself](/getting-started/add-a-box#agent-clis-you-installed-yourself)), and `agents install` skips it |
| `berthd pair [--address HOST[:PORT]] [--ttl 10m] [--json]` | Print a single-use pairing link; `--json` prints `{ link, address, fingerprint, expires }`, which the laptop agent reads to pair with this computer's own berthd ([Use this Mac](/getting-started/add-a-box#this-mac)) |
| `berthd clients` | List paired laptops |
| `berthd revoke <name\|fingerprint>` | Stop trusting a laptop |
| `berthd id` | Print this box's fingerprint |
| `berthd doctor [--json]` | Check this box's setup and how to fix it. It looks for the agent CLIs afresh, and names each one's version, path and how it was installed |
| `berthd version` | Print this build's version |
| `berthd session attach NAME` | Attach to a session in this terminal |
| `berthd mcp` | A stdio MCP server of Shipyard's tools for agents on this box, talking to its socket; `integrations install` adds it to Claude Code, Codex and Gemini CLI ([runs](/guides/runs#from-an-agent-mcp)) |
| `berthd headless --agent A --out FILE.jsonl --prompt-file FILE [--read-only] [--add-dir D]` | One non-interactive agent turn, as runs start in tmux for judges and reviewers |

`~/.berth/runs.json` on the box sets `max_concurrent_runs` (10),
`max_concurrent_agents` (6) and `triggers_listen` (`"tailnet"` serves signed
[webhook triggers](/guides/automations#from-a-webhook) on the tailnet
address, port 7482). Runs that were going when berthd stopped resume when it
starts.

## Locations and worktrees

| Command | What it does |
| --- | --- |
| `berthd locations [--json]` | Locations and their worktrees |
| `berthd location add NAME PATH` | Register a repo or directory |
| `berthd location rm NAME` | Forget a location (files are untouched) |
| `berthd location scripts NAME [--setup CMD] [--archive CMD] [--clear]` | Worktree setup and archive scripts (default: the repo's `.berth/config.json`) |
| `berthd location config NAME [--json] [--trust HASH\|--untrust]` | The repo's, the box's and the effective config; trust the repo's to run it |
| `berthd services [--json]` | Which worktree each running server belongs to |
| `berthd service list\|start\|stop\|restart\|log LOC/WORKTREE [SERVICE]` | A worktree's services from the repo's config |
| `berthd preview [LOC/WORKTREE] [PORT] [--path /x]` | Open a worktree's page in the Shipyard app |
| `berthd worktree new LOC/NAME [--branch B] [--base REF] [--pr N [--ref REF]] [--parent NAME]` | Create a git worktree and run its setup; `--pr` checks out that pull request (pass its head branch as `--branch`; a fork's head comes from `--ref`, by default `pull/N/head`); `--parent` nests it under another worktree of the location |
| `berthd worktree rm LOC/NAME [--force]` | Remove a worktree |
| `berthd worktree rename LOC/NAME [TITLE]` | Give a worktree a display name (no TITLE clears it) |
| `berthd reviews [--idle-days N] [--json]` | The [pull requests opened for review](/guides/review-a-pr) here; `--idle-days` sets how long one may sit unused before it is cleaned up (`0`: never; default 7) |
| `berthd review-button [LOC/WT] [--as EMAIL] [--path /x] [--clear] [--json]` | The [Review in Shipyard button](/guides/review-a-pr#the-review-in-shipyard-button) on the worktree's PR: whether the project has it on, and whether the PR has it. `--as` (one of the project's login users) and `--path` set what it opens with; berthd puts the new link in place on its next look. `--clear` drops both |
| `berthd login users [LOC[/WT]] [--json]` | The users the project's worktrees can be logged in as, from its trusted login config: what a review link's `as` may name |

`berthd preview` with no arguments uses the worktree it runs in (from
`$BERTH_WORKTREE_PATH` or the current directory) and its `$BERTH_PORT`. It
asks the app to open the page as a browser tab beside the agent; the
`berth-preview` skill teaches agents to use it.

## Agent sessions

| Command | What it does |
| --- | --- |
| `berthd sessions [--json]` | List sessions |
| `berthd agents [--json]` | Agent CLIs this box can start |
| `berthd task new LOC/NAME [--agent ID] [--prompt TEXT] [--open split\|tab] [--branch B] [--base REF] [--no-notify] [-- COMMAND...]` | A worktree with an agent (or a command) running in it; from an agent's session, that agent [hears back](/guides/orchestration#hearing-back) when its first turn ends, and the new worktree nests under that agent's |
| `berthd session new LOC[/WORKTREE] [--name N] [--agent ID [--prompt TEXT]] [--open split\|tab] [-- COMMAND...]` | Start an agent or a command (default: a shell) there |
| `berthd session screen NAME [--history N]` | Print what the session shows |
| `berthd session send NAME TEXT [--when now\|idle] [--force] [--idem KEY] [--no-enter] [--wait [--timeout 30m]] [--no-notify]` | Type a prompt into a session (or hold it until the agent is idle), and wait for its turn; without `--wait`, an agent sending it hears back when the turn ends |
| `berthd session wait NAME [--turn ID] [--for finished,waiting] [--timeout 30m]` | Wait for a turn (from `session send`), or its agent's current one, to end |
| `berthd session turns NAME [--limit 10] [--json]` | List a session's turns: who prompted, how it ended, how long it took |
| `berthd exec LOC[/WORKTREE] [--timeout 10m] [--detach [--no-notify]] -- COMMAND...` | Run a command there and print its output; `--detach` runs it as a run, which reports back to an agent that started it |
| `berthd loop SESSION --check CMD [--prompt TEXT] [--max 5] [--turn-timeout 30m] [--cancel-on-exit] [--detach]` | Prompt, wait, check, and feed failures back, as a durable run |
| `berthd runs`, `berthd run start\|get\|logs\|approve\|reject\|cancel\|templates …` | [Runs](/guides/runs), as `berth run` without the box |
| `berthd browser open\|snapshot\|click\|fill\|press\|select\|hover\|check\|wait\|shot\|console\|network\|eval\|status\|close [LOC/WT] …` | The worktree's [agent browser](/guides/agent-browser); inside a session, its own worktree |
| `berthd browser open [LOC/WT] --as EMAIL [--path /x]` | Log the agent browser in as one of the project's [dev users](/guides/kits#personas-logging-in-as-a-dev-user) (the worktree's login script runs, its cookies go in for the worktree's address), then open the page: `--path`, else where the login says |
| `berthd browser list`, `berthd browser allow ORIGIN`, `berthd browser install` | Browsers running; allow a public origin; download a Chromium |
| `berthd browser reap [--dry-run] [--json]` | Close the [agent-browser](/guides/agent-browser#agent-browser) sessions (Vercel's CLI) that Shipyard sessions which have ended left running; `--dry-run` only lists them. `berthd doctor` reports them too |
| `berthd shots compare [LOC/WT] [--pages / /login] [--sizes 375 768 1280] [--base main\|turn-start\|accepted\|NAME] [--mask SEL]... [--color-scheme light\|dark\|both] [--as EMAIL] [--title T] [--note N] [--new]` | Screenshot the worktree's pages and the base's, diff them, and keep a [visual diff](/guides/visual-diffs); a re-run is its next version. Prints what changed, in about 450 tokens. `--as` logs both sides in as a [dev user](/guides/kits#personas-logging-in-as-a-dev-user), each with its own login |
| `berthd shots baseline [LOC/WT] [--name turn-start] [--pages …] [--sizes …] [--color-scheme …]` | Save the worktree's pages as a baseline to compare with later |
| `berthd shots accept [LOC/WT] ID` | Keep a visual diff's after-shots as the worktree's `accepted` baseline (the app's **Accept as baseline**) |
| `berthd flow secret FLOW [--scope S]` | Make a webhook flow's signing secret |
| `berthd session rename NAME [TITLE]` | Name a session's work; no TITLE clears it |
| `berthd session kill NAME` | Stop a session |

## Ports and sharing

| Command | What it does |
| --- | --- |
| `berthd ports [--json]` | What is listening on the box |
| `berthd stats [--json]` | Memory, disk, load, and agents running or waiting |
| `berthd ps [--json]` | Every [browser on the box](/guides/agent-browser#every-browser-on-a-box) with who started it, its CPU, memory and age, and what each session's processes use |
| `berthd ps stop ID` | Stop a browser from that list (an ID like `b-4182-…`), or end a session (`s-NAME`) and everything it started |
| `berthd info` | The box's name, OS, build, tools and agent presets, as JSON |
| `berthd share PORT` | Make a port public (Cloudflare quick tunnel; needs `cloudflared`) |
| `berthd shares [--json]` | List public shares |
| `berthd unshare ID` | Stop a share |

## Units

Long-running programs berthd runs under the box's service manager, so they
survive reboots and restart on failure. Their output goes to a log berthd
owns, not the journal.

| Command | What it does |
| --- | --- |
| `berthd units [--json]` | Managed units |
| `berthd unit add NAME -- COMMAND...` | Install and start a unit |
| `berthd unit get NAME [--json]` | Its state and where its log is |
| `berthd unit log NAME` | What it has written, for one that will not stay up |
| `berthd unit restart NAME` | Start it again |
| `berthd unit rm NAME` | Stop and remove it (its log stays) |

## Skills, secrets and events

| Command | What it does |
| --- | --- |
| `berthd skills [list\|install\|uninstall] [SKILL...] [--agent claude\|codex\|all] [--target user\|project] [--location LOC] [--commit]` | Teach Claude Code and Codex to use Shipyard |
| `berthd secret test REF` | Check this box can resolve `op://vault/item/field` or `env://NAME` (prints the value's length, never the value) |
| `berthd secret exec [--socket PATH] -- PROGRAM [ARGS...]` | Used by sessions and services: resolves secret references, then runs the program. See [secrets](/guides/secrets#how-values-are-handled). |
| `berthd secret signin [--check]` | Signs the box's `op` in to 1Password in this terminal (`op signin`) and keeps its session for berthd's `op://` reads; a team setup's 1Password step runs it. `--check` asks nothing and exits 0 when berthd can read 1Password now. See [secrets](/guides/secrets#setting-up-1password-on-a-box). |
| `berthd emit TYPE [key=value...] [--origin TOOL]` | Announce an event, e.g. `deploy.finished` |
| `berthd events [--json]` | Stream the box's events |

## Integrations

| Command | What it does |
| --- | --- |
| `berthd integrations [status]` | Where Shipyard's hooks and skills are for each agent CLI on this box, per Claude Code and Codex account (`Claude Code: hooks and 7 skills in ~/.claude, ~/.berth/accounts/claude/personal`), and the command that adds them where they're missing |
| `berthd integrations install claude\|cursor\|codex\|gemini\|opencode\|all\|present` | Install Shipyard's skills and agent hooks for a tool (`present`: every agent CLI on this box, quietly skipping the rest), and `berthd mcp` as an MCP server for Claude Code, Codex and Gemini CLI. Claude Code and Codex get them in [every account folder](/guides/agent-integrations#every-account) |
| `berthd hook TOOL EVENT [PAYLOAD]` | What those hooks run: turns a tool's hook into a Shipyard event (`agent.finished`, `agent.waiting`), naming the session from `$BERTH_SESSION`. While berthd is down it keeps the event in `~/.berth/box/spool/`, published when berthd starts |

See [agent integrations](/guides/agent-integrations) for what the hooks and
skills do, and [the berth CLI](/reference/cli) for the laptop's side.
